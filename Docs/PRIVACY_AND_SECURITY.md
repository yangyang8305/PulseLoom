# 隐私与安全交接

## 当前数据流

| 数据 | 保存/发送 | 默认与删除 |
|---|---|---|
| 自创、收藏、主题、组合 | 本地Application Support；用户开启同步后指定部分到私有CloudKit | 本地清理/导出；云端单独删除 |
| 音频文件 | 本地临时位置及解码内存；不进入CloudKit和relay | 替换/服务清理临时文件；保存配置不保存音频 |
| 音乐配置 | 配置名、原文件名、mapping/强度/区间等本地 | 配置删除；备份可能包含文件名 |
| 使用历史 | 本地Private目录，排除系统备份 | 默认关闭，100条/30日，手动清空 |
| 反馈 | 用户输入本地保存，导出后由用户选发送渠道 | 手动删除/导出 |
| 诊断 | OSLog允许代码＋可选本地环形事件；无自动业务上传 | 事件500条/7天上限；导出前可检查 |
| 购买 | Apple StoreKit处理、客户端验证 | 不保存卡号；恢复和退款由Apple流程 |
| 系统音乐 | Apple Music/MusicKit处理授权与歌曲请求 | 用户许可；DRM不绕过 |
| 远控 | HTTPS/WSS传输密文；中继保留短期房间/IP等元数据 | 1小时房间到期/重启消失；邀请码必须保密 |
| Watch/Widget | WCSession和App Group，必要模式名/强度/状态 | 手机许可默认关闭；Widget可隐藏模式名称 |

没有广告SDK、ATT追踪、HealthKit、位置、麦克风/摄像头/通讯录请求；敲击录制是触摸时间记录，并非录音。使用系统音乐授权不会取得其他App的任意PCM。

## Manifest 与 App Store标签

三个target都包含 `PrivacyInfo.xcprivacy`。App需要的Required Reason API理由包括自身/共享偏好、相对计时、用户文件大小/时间检查。文件中的理由是按当前用途声明的起点，归档扫描后须与系统实际报告复核；添加SDK或更改用途须重新审查。

**不能照原型写“无数据收集”直接提交。**正式App启用CloudKit、MusicKit及自部署中继后有真实网络数据流，运营主体、支持渠道、IP保存策略、Apple服务与跨境处理必须如实披露。当前提供文档和Manifest，不代表法律审查或App Store隐私标签已通过。

`ITSAppUsesNonExemptEncryption` 初始值需要发行方根据实际CryptoKit/TLS用法及出口合规要求复核，不能据此宣布无需任何出口手续。

## 安全规则

1. Receiver 默认拒绝、再次连接需要重新确认；对方不可撤销用户的停止权。
2. 新连接随机nonce、AES-GCM AAD绑定房间、单调sequence防旧消息重放；无需让中继持有解密key。
3. 不在连接URL查询字符串、日志、诊断里暴露capability或AES key。邀请是机密数据，不用于公共分享/反馈附件。
4. 不在Git提交Local.xcconfig、Apple密钥、签名证书、`.env`、令牌。发布脚本检查常见私密扩展。
5. 输出遵循前台/温度/时间范围；没有后台保活音轨、私有API或硬件超频。
6. JSON限定schema与大小，禁止任意脚本/路径执行；UTF文本用于显示需原生Text而非HTML执行。
7. 本次没有独立渗透测试、依赖漏洞扫描或第三方安全认证。
