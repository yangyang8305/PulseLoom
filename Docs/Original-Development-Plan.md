## 1. 项目定义、用户与目标

### 1.1 产品愿景与承诺

用户打开App后能快速选择一种触感，明确调整其强弱和节奏，在短时会话中体验，并保存自己的模式。价值来自可理解、可复现、可停止的触觉控制。

对外承诺限于：预设节奏、自定义录制、相对强度控制、定时停止、主题和本地保存。对外不承诺：肌肉治疗、疼痛缓解、焦虑治疗、治疗失眠、达到专业按摩设备强度、提高手机物理振动能力。

### 1.2 用户与任务假设

| 用户假设 | 用户要完成的事 | 核心路径 | 验证方法 |
|---|---|---|---|
| 希望短时放松的成年人 | 少设置地体验可调整的轻触节奏 | 首页→播放→调整→停止 | 12–20名成年人可用性测试 |
| 关注触觉反馈的工具用户 | 分辨节奏、强弱、质感差别 | 模式库→详情→编辑副本 | 模式辨识测试、访谈 |
| 喜欢自定义的用户 | 录下自己的节奏，下一次再次使用 | 创建→敲击→预览→保存 | 首次保存成功率 |
| 隐私敏感用户 | 不注册、不上传即可用核心功能 | 跳过可选说明→本地使用 | 权限审查、网络流量核验 |

以上是待验证用户画像，不包含未经研究支持的年龄分布、性别比例或市场规模。

### 1.3 非目标

首版不做成人内容、社区、聊天、社交任务解锁、外设控制、远程控制、医疗服务、AI生成内容、健康数据采集、睡眠监测、音乐库接入、锁屏持续震动、无限时长后台服务、跨平台Web播放器。

### 2.2 五个重点样本如何影响本项目

**iVibe：**参考其模式工具定位及多种解锁商品；本项目缩减首版商品数量，只保留一个Pro非消耗型内购，减少价格解释成本。未核实其首屏、具体付费墙时机和全部皮肤结构，不将这些作为界面事实。[R01]

**HapticVibe：**开发者描述包含强度、sharpness和速度，更新记录提及XY控制及录制。由此形成“基础参数有学习门槛”的产品假设，本项目采用“强弱／质感／间隔”的中文语义，XY与节点曲线后置。[R03]

**uFeel：**功能宣传把模式、录制、音乐、远控放在同一产品中。可作为长期功能扩展参考，但首版不复刻全部模块，以免音频会话、权限与网络状态同时进入关键路径。[R02]

**iMassage U：**10种模式与3档强度应分开统计。其后台与增强描述未经本次真机验证，不能作为本项目Core Haptics能力依据；本项目保留手机本体的体验优先级。[R05]

**Strong Vibration：**以自定义、远控等扩展覆盖不同需求。本项目将远控定义为独立后续实验，必须通过前台状态、确认授权及随时停止的验收后再发布。[R04]

### 3.2 免费与Pro配额

免费用户有完整的播放、最大相对强度、停止、定时、故障排查、隐私及无障碍能力；这些不因付款增加硬件能力。免费可保存3个自定义模式；Pro为200个本地保存项的技术上限。达到200个时提供整理指引，不宣传“无限”。删除旧模式可以释放配额；编辑已有模式不消耗新名额。内置模式创建编辑副本时占一个名额，且Pro内置内容的副本携带对应权益来源，不通过复制绕过内容解锁。

退款或未来订阅失效时：内置付费内容不再新播放；用户原创数据不删除。已保存的自创模式保持可读、可播，超额时限制新建，避免用数据访问强迫续费。涉及Pro内置内容派生的副本保留但只读预览。

**从上到下的结构及CTA：**版本/build→基础教程→前台边界→模式说明→许可→联系支持。

**控件与操作：**邮件由用户主动打开并检查；诊断附件可选预览后导出。

**默认值：**只预填版本与OS；不自动附自定义节奏或身份。

**Loading／Empty／Error／Disabled：**无邮件客户端给可复制联系方式；网络失败不阻挡本地教程。

**手势、动效和反馈：**继承系统返回、按钮按压100毫秒和选择切换180毫秒；不依赖隐藏手势完成主操作。触觉正在播放时关闭额外装饰性触觉，避免干扰内容；录制页只执行被明确记录的触觉。减少动态效果时关闭非必要波形动画。

**事件及权益：**help_open、support_export_requested；无。事件默认为本地诊断设计，不代表自动上传。

**验收：**继承G01–G08，另需满足：显示真实构建号；无医疗效果保证；支持地址上线前验证可达。

首屏优先级：停止、播放/暂停、相对强度、剩余时间。小屏和大字号时先压缩波形，再把快捷模式移到下方滚动区；不把停止挤出屏幕。首页不常驻大幅付费Banner。主按钮和强度落在屏幕中下区域，拇指无需到顶部完成核心会话操作。

### 6.2 模式切换、预览与主会话

播放中点击另一个可用模式：提交新选择→校验→停旧player→创建并开始新player→更新波形，保留本次剩余计时和主强度。目标为可感知切换间隔≤200毫秒，属于验收目标，须真机测；失败则停止并显示明确错误，不冒充切换成功。

正在播放时打开编辑器、敲击录制、预览或付款页：先暂停主会话。返回时保留剩余有效时间，由用户点击继续。模式库普通浏览不影响主会话，页面底部显示迷你控制条。

### 6.3 防误触与屏幕管理

“前台防误触”仅锁模式选择、强度和快捷手势；独立停止始终可点击。它不等于系统锁屏。播放会话期间可使用系统idle timer防止自动休眠，默认开启，设置中可关闭；暂停、停止、异常、后台、离开有效会话时立即恢复系统原本休眠行为。不得依赖调高亮度或播放静音音频来保持进程。

## 7. 触觉引擎、技术边界与状态机

### 7.1 官方边界与本项目动作

| 事项 | 已知事实或证据限制 | 产品／工程动作 |
|---|---|---|
| 强度与质感 | Apple用0–1描述intensity与sharpness；后者是触感质地，不是可自由指定的马达Hz。[R11][R12] | 前台用“强度／柔和—清晰”，不做“200Hz治疗频率”输入 |
| 连续事件 | 单个hapticContinuous最长30秒。[R13] | 单个连续片段限定≤10秒；长会话用合法短模式循环 |
| 后台/锁屏 | 应用被后台挂起可让引擎停止。[R14] | 首版进入非active就停止输出；不依赖后台延长技巧 |
| 引擎复位 | 需按实际API处理停止、重置和重新准备 | 不无限重试，不从回前台事件自动开始触觉 |
| 设备能力 | 能力检测并不证明用户实际感觉到了振动 | 能力检查＋明确测试＋用户确认 |
| 发热和电量 | 本次没有跨机型功耗实测，不能给出统一每分钟耗电量 | 限制会话、降动画、记录测试条件；thermal serious/critical时停播为产品策略 |

### 7.2 对象职责

`SessionCoordinator`是单一事实源，管理状态、所选模式、主强度、计时和输出占用者。`PatternCompiler`将项目JSON转换为Core Haptics事件，`HapticDriver`封装引擎及player，界面不能直接各自创建引擎。

输出占用者枚举：none／main／preview／recording。任意时刻仅一个。录制和预览不能与主会话同时运行；购买UI弹出前释放占用。

### 7.3 状态与转换

| 当前状态 | 触发 | 下一状态 | 输出／数据动作 |
|---|---|---|---|
| Idle | 点击播放且兼容／有权益 | Preparing | 校验、申请输出所有权、准备player |
| Preparing | 成功 | Playing | 建立单调时钟锚点；启动有效计时 |
| Preparing | 失败 | Error | 释放输出，展示错误码与重试 |
| Playing | 用户暂停 | Paused | 停输出；保留剩余时间与估算相位 |
| Paused | 用户继续且仍active | Preparing→Playing | 重新核验可用条件，恢复或从周期起点重播 |
| 任意输出态 | 独立停止 | Idle | 立即停player；计时任务失效；释放休眠控制 |
| Playing | 系统inactive/background／音频中断 | Interrupted | 立即停输出、冻结有效时长；落盘必要元数据 |
| Interrupted | 回前台 | Paused | 只恢复UI；提示点击继续 |
| Playing | 剩余时间≤1秒 | Ending | 进行约1秒设计淡出；无法淡出也须按时停止 |
| Ending | 到时 | Completed | 停引擎输出、归档、恢复系统休眠 |
| 任意 | 引擎reset | Interrupted | 失效所有旧player，准备新engine但不擅自开始 |
| 任意 | 不支持触觉 | Unsupported | 关闭播放CTA，保留浏览与故障帮助 |
| Playing | thermal serious/critical | Interrupted | 产品层主动停止；显示设备温度状态说明 |
| Paused/Interrupted | 连续无操作超过5分钟或App被终止 | Idle | 结束旧会话；下次从模式选择态开始 |

UI防误触是单独布尔状态，不与系统Locked混为一种播放状态。低电量模式默认减动画；不宣称系统低电量模式必然关闭触觉。电量值未知时不显示假读数。

### 7.4 时间与并发

计时使用单调时间概念，持久化历史时间使用Date；改系统时间不能延长正在运行的会话。UI每秒显示剩余时间不承担实际节奏调度。事件相对时间由Core Haptics播放器执行，禁止以主线程Timer逐拍触发UIFeedbackGenerator模拟模式。

每次启动、切换和停止都有generation/session ID；异步旧回调不得覆盖新会话。停止高于开始和预览优先级。快速连续点击按顺序归并，不创建多条输出流。错误处理不能使用吞掉所有异常的空catch。

### 7.5 参数编译策略与POC门槛

首版把节奏设计成有限事件序列：每段保存自己的相对时间、时长、基础强度与质感；主强度由单一动态控制通道负责。渐变预设先采用分段近似，波形也按相同事件绘制。连续曲线与实时主增益叠加留给独立POC，不假设多个同ID参数曲线会按预期相乘。[R21]

首周必须测试：连续分段接缝、暂停/恢复、循环端点、0强度、快速滑杆更新、模式切换、引擎reset。若接缝无法满足体验，先调整预设或编译方式；在验收前不宣传“无缝平滑曲线”。

播放器目标使用CHHapticAdvancedPatternPlayer的暂停、恢复、循环等能力；具体API和支持条件在所选SDK中编译核验。[R24] 若相位恢复无法可靠实现，v1采用“恢复从当前模式周期起点继续”的明确策略，仍保留计时，UI不显示虚假的精确进度。

## 9. 自定义编辑器完整规格

### 9.1 四种编辑方式的取舍

| 方式 | 优势／成本假设 | 版本决策 |
|---|---|---|
| 基础滑杆＋分段列表 | 易做数值校验、易支持VoiceOver；复杂节奏编辑较慢 | v1必做，4段初始、最多16段 |
| 可视时间轴 | 便于理解时长和间隔；拖动、缩放、选区冲突增多 | v1只读时间轴＋点选段；完整拖拽v1.2 |
| 敲击录制 | 无需理解参数即可创建节奏；需要处理触摸取消和时序 | v1必做，录完后审阅保存 |
| 节点曲线／XY控制板 | 连续变化直观；动态曲线与主强度的组合需额外验证 | v1.2或更晚，不进入首发承诺 |

### 9.2 字段与规则

| 字段 | 首版约束 | UI形态 |
|---|---|---|
| 名称 | 1–30个用户可见字符；去首尾空白；允许重名但保存ID独立 | 文本框，计数与错误说明 |
| 段数 | 1–16；录制模式可存更多事件，最多128个 | 段列表、加段、复制、删除 |
| 基础强度 | 0–1，UI 0–100%，1%步进 | 滑杆＋可访问增减 |
| 质感 | 0–1，UI柔和—清晰；默认0.25 | 滑杆；帮助气泡 |
| 输出时长 | 基础段50–2,000毫秒；录制连续段≤10,000毫秒 | 50毫秒步进＋数值输入 |
| 间隔 | 0–2,000毫秒；高级长留白由多个段表达 | 50毫秒步进 |
| 总周期 | 100–30,000毫秒；不可超过会话边界 | 自动求和显示 |
| 循环 | 开/关；开时仍受会话定时限制 | Toggle，默认开 |
| 预览 | 最多8秒；非循环内容提前结束 | 播放/停止，不自动重复计费 |
| 撤销/重做 | 最近30次编辑动作；拖滑杆的一次手势算一次 | 工具栏按钮 |
| 草稿 | 修改结束后约500毫秒防抖持久化；后台立即尝试保存 | 本地Draft，不占正式保存名额 |

基础草稿最多16段，录制草稿最多128事件；两种模式复用页面，但各自保留编辑模式标记。录制事件支持选取、数值修改、删除；转为基础编辑须另建副本，超出16段时阻止转换并保留原草稿，不静默截断。录制形成的长间隔保持原值；基础新建间隔上限2,000毫秒不追溯改写录制数据。录制达到128事件时停止接受新事件，保留已完成内容并提示已达上限。

全静默模式不能保存为有效触觉模式，提示“至少保留一个有强度的片段”。NaN、Infinity、负时长、越界索引、未识别事件类型、超长总周期一律拒绝。首版自定义事件不允许重叠，避免把混合行为隐藏在基础UI内。

### 9.3 用户流程

创建：我的→创建→选基础或敲击→编辑→显式预览→输入名称→校验→检查配额→原子保存→成功回我的。配额不足时保留全部草稿，用户可以购买、删除旧项或返回继续编辑。

编辑：进入已有自创模式→建立工作副本→修改→保存替换原记录版本；取消时可恢复原件。复制：生成新UUID与“原名 副本”，原件不修改。重命名：只改显示名和updatedAt。删除：确认→删除记录→清理收藏→若当前播放同项先停止。

敲击录制：进入录制页→点击开始→显示录制状态→记录首触点down/up时间→停止→去掉首次触摸前的空白→保留段间间隔→自动生成100–300毫秒尾部留白且总长不超过30秒→预览→使用回编辑器。原始高频触摸轨迹不持久化，只存时序事件。

### 9.4 后续高级编辑约束

v1.2时间轴支持1×/2×/4×缩放、节点拖动和数值替代操作。曲线节点单模式最多64个，时间单调递增，默认线性插值。节点离散取值与最终动态参数映射由CurveCompiler定义，未经POC不暴露伪Hz或“增强倍数”。导入文件必须有schemaVersion，解析失败保留原草稿。

## 10. 设计系统与主题交付

### 10.1 视觉方向

默认采用“墨夜/素白”成对基础主题：中性底色、清晰文本、局部绿色强调、较低装饰密度。第二方向为海蓝/青玉的冷色工具风，第三方向为暮紫/陶土的暖色个人化风。三方向是本项目提案，未声称已由竞品验证。

原生导航、Sheet、Tab和开关优先。材质只用于导航或浮层，波形与文本区域使用稳定对比度背景。不给每个卡片堆积玻璃、阴影、发光和连续动画。字体统一系统字体，不下载特殊字体。

## 11. 商业化、付款流程与价格实验

【依据】样本中有$3.99、$4.99、$9.99、$24.99等不同一次性或Lifetime标签商品；本项目价位处于其间，但产品不同，不能据此推导用户愿付价格。[R01][R03][R05][R07] 本方案不依赖持续内容更新收费；Apple的订阅说明强调持续价值。[R18]

### 11.3 付费墙触发规则

仅在用户主动打开Pro、点击付费预设的完整播放、应用Pro主题、保存第4个新模式时出现。首次触感测试前不出现；播放中不插入；返回App不自动出现。取消后不定时再弹；重复触碰受限项先展示小型权限说明，再由明确“查看Pro”打开购买页。无虚假倒计时、优惠原价、默认勾选续费、隐藏关闭、评分解锁或分享解锁。

### 11.4 StoreKit实现契约

商品加载、交易购买、签名验证、权益归并和UI展示分层。应用启动建立交易更新监听，并重算有效权益；购买成功以验证结果为条件，不能仅看系统购买窗关闭。监听任务生命周期跟App一致，离开付费页不能取消它。

`AppStore.sync()`用于用户主动恢复的同步入口。[R19] `Transaction.currentEntitlements`、交易更新和验签的具体实现以当前SDK为准，R23作为编码对照入口；本次网页正文受JS限制，不能将该页的未读细节写成已逐项核实事实。

待批准、取消、未验证、已撤销、网络不可用均有独立状态。对已验证交易幂等授予权益并完成交易处理；清除本地内容不抹去App Store购买资格。离线时无法获知刚刚发生的退款，明确这一同步边界；恢复联网后刷新。不得用一个可修改的UserDefaults布尔值替代交易验证。

首版用Apple支付，无站外支付、兑换码服务器或微信收款。退款入口调用受支持的系统流程或跳转Apple官方退款渠道；退款结果由Apple决定，文案不能写“点击即退款”。

### 12.2 关系和存储选择

采用SwiftData存储自定义、收藏和可选历史，JSON目录提供16预设；复杂PatternEvent数组可作为带schema版本的可编码payload保存，由Repository统一读写。不存在云端业务数据库。为避免历史被用户内容备份连带保存，将历史和诊断与自创内容分开存储。

自创内容及收藏允许操作系统备份；这不等于App内iCloud同步，也不保证用户换机时数据一定恢复。政策必须分别说明“本地保存”“系统备份可能性”“首版无账号云同步”。

### 12.3 迁移、删除与故障

SchemaVersion与内容版本分别管理。升级流程先验证旧库→在临时副本迁移→完整校验→原子替换；失败保留旧库和恢复入口。测试构造v1旧数据、空库、孤立收藏、超长名称、重复ID、损坏payload等样本。

清除本地数据显示清单：自创模式、草稿、收藏、历史、主题偏好和诊断；默认不触碰StoreKit交易。清理完成后重新读取权益，只回到选择态。不能把“清库”实现成删除整个容器后意外丢交易监听状态。

### 14.2 隐私标签与Manifest

【事实】Apple要求说明App及所集成第三方代码的数据处理实践；不能只看自己写的代码。[R17] UserDefaults属于需要检查Required Reason声明的API类别，适用理由应与实际用途一致；仅本App偏好用途可核对CA92.1。[R20]

操作：上线前生成“字段→去向→用途→保存期→是否与身份关联”的数据清单；扫描Release归档与依赖；核对隐私Manifest；再填写App Store隐私标签。只有实际符合时才申报Data Not Collected。用户主动联系客服、提交诊断、服务器访问日志等仍需按规则评估，不因“可选”两个字自动免除披露。

### 14.3 本地安全

只解析白名单字段，不从文件执行代码。未来导入体积上限设为256KB，超过拒绝；schema未知不猜测解析。自创名称不进崩溃日志；应用退后台时增加中性快照遮罩，隐藏模式名称和历史。这是减少曝光措施，不宣称能阻挡系统所有截图或取证方式。

使用iOS数据保护和应用沙盒；锁屏前优先保存草稿，受文件保护拒绝写入时保留恢复策略，不关掉保护以图省事。导出诊断默认仅包含App版本、OS大版本、能力标记、错误码和时间相对顺序，不包含完整购买凭证。

### 14.4 隐私政策最小结构

必须有运营主体、联系邮箱、生效日、功能与数据对应表、本地内容与系统备份说明、Apple处理购买说明、可选支持数据、保留/删除方法、第三方与跨境处理（如实际存在）、更新机制。法律主体与联系方式是上线前待填字段，不能在提交版使用示例占位地址。

### 17.3 严重度与发布阻断

P0缺陷：无法停止、后台意外输出、未经验证解锁、错误扣费路径、数据丢失、启动崩溃。P1缺陷：主要机型无法播放、恢复购买失败、核心无障碍流程阻断、明显模式接缝或计时错误。发布条件为P0/P1未解决数为0；P2视觉与边缘问题须有记录及可接受理由。

所有16预设在至少3种实体机上人工确认有可辨识节奏；这不是对强度一致性的保证。工程日志记录软件调度耗时，物理振动开始/结束若要量化必须另配传感器/测量方法，不把屏幕动画时间当作硬件时延。

### 17.4 能耗实验方法

固定屏幕亮度、系统版本、环境温度、手机壳条件、初始电量和网络状态；同机比较静态前台基线、动画空跑、实际播放三种条件，每种至少3轮。只报告所测机型的增量电量消耗和thermal状态。出现serious/critical立即按策略停止，不继续压测追求“最大功率”。产品的10分钟上限不是经医学验证的安全使用时长。

### 19.3 工作量与预算模型

工程首版估算320–400小时，设计80–120小时；另有40–60小时手工回归需求，其中部分由工程/设计工时覆盖，具体分工先写入排期，避免重复计费。产品评审20–30小时。以上是按本规格建立的估算，不是外包报价或行业统计。

预算用公式：工程小时×内部或合同费率＋设计小时×费率＋未覆盖QA＋设备/开发者账户/素材费用＋20%变更储备。例：工程360小时×¥8,000＋设计100小时×¥6,000＋额外QA40小时×¥4,000＝¥3,640,000；加20%储备为¥4,368,000。单价是假设，未计税、硬件及Apple账户费用；自行开发则主要体现机会成本。

开发环境至少需要能运行所选正式Xcode的Mac及多台实体iPhone。是否已有设备、实际合同费率和Apple账户状态属于尚未取得的项目输入，不假装已确认。纯单人且设计/测试也由同一人承担时，以12–16周作资源计划假设，再按W1实测速度重估。
